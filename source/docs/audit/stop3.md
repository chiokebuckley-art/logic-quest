# Stop 3 · Line Up: wrong-answer audit

Every Stop 3 item carries the full teaching from the wrong-answer handoff (v1.0):

- a rule;
- 1–4 terms defined in the skin's own words (four only for a "not first" plus "not last" item, which needs both words, "Can’t tell" and "To break a clue");
- what the key clue or sentence means;
- 2–4 worked lines;
- a Remember line with a question;
- a smaller worked example ("Explain more simply").

A worked line is a card such as "Finish order: Ava, Ben, Cal." Its clue truths are computed by `clueHolds`:

- The item's worked lines try many orders, so each card lists only the clues that line breaks. A line that fits lists none, and its note says "Every clue is true here." The right line in lesson 4 is the exception: it lists every clue, because that lesson is about checking each clue in turn.
- The example under a chosen answer lists every clue when its line fits, and the broken clues when it does not, plus "Your answer" or "The sentence" where one is involved.

Each note is chosen from those truths, and each smaller example is a small puzzle solved by brute force. Every wrong choice of every choose item has its own `ChoiceFeedback`, keyed by a content-derived id. It has a headline naming that answer's gap, detail with labelled orders, and a counterexample line.

The first pass (branch `wa-stop3`) also fixed four problems:

- Lesson 5 choice ids were positions (`k1`…`k5`). They are now clue ids such as `before-ava-ben`.
- Lesson 3 skill tags followed whichever clue was shuffled first.
- Two prompts had vague directions: "Must it be true?" and "first" in a line or parade.
- One message claimed to know the player's thinking ("You read “before” as…").

A second review (branch `wa-stop3-v`) found ten more; see "Second review" below.

`StopDef.fresh` gives one equivalent new example after a miss. It has the same generator, skill and kind of answer, with other names.

Code: `src/engine/puzzles/lineup.ts` (teaching section and each generator), `src/content/stop3.ts` (`fresh`, lesson 3 and lesson 4 cards). Tests: `src/engine/__tests__/lineup.test.ts` (48 tests). They use a second clue checker written apart from `clueHolds` to re-check every truth, note, quoted order and smaller example. Mutation runs (flipped truths, swapped examples, false notes, and each second-review fix undone) each fail the suite.

## Terms used below

- **Line card**: a `TeachCase` such as "Finish order: Ben, Ava, Cal.", listing "Clue 1, “Ava finished before Ben”: false." and so on, plus "Your answer, “Ben finished first”: true." where a pick is involved. Truths are computed, never typed in.
- **Best try**: the order that puts the picked name (or spot) where the answer says and breaks the fewest clues. If even this order breaks a clue, every order like it does.
- **Fresh check**: `stop3.fresh` builds one new item from the same generator with the same skill and kind of answer: "Can’t tell" or a name, the same must/might/can’t status, the same conflict, the same where/who question, and the same line length. If no match turns up in 30 draws, it returns `[]` and the default applies (the same skill from the lesson's practice).

## Shared changes suggested

All three were made after the migration. `stop3.fresh` gives lessons 1 to 3 a pair of new examples, in random
order: one built like the missed item, and one with the other kind of answer (“Can’t tell” with a decided one,
“must” or “can’t” with “might”). A line-up miss quotes each broken clue and says where the line breaks it (“Clue 1
says “Storm has the second longest wings.” In your line, Storm is first, not second.”). The player’s own line is shown
as a card, with each clue true or false for it. Tests: `lineup.test.ts` (“a miss gets a new example built the same
way …”) and `wrong-answers.test.ts` (“where other kinds fail”). As first written:

- `src/content/stop3.ts` `fresh` with `src/game/__tests__/wrong-answers.test.ts`: give lessons 1 and 3 a set of two new examples, one “Can’t tell” and one with a single answer, in random order. Give lesson 2 a must or can’t with a might. Then a player cannot pass by repeating one answer. That test now expects exactly one new example for each Stop 3 lesson (“other misses get one new example …”), so it must change in the same commit.
- `src/game/explanation.ts`, order items: show the player's own line as the example card, with each broken clue's truth from `clueHolds` and the clue texts from the scene. Then a build miss shows exactly where the line fails, not only "This line breaks clue 2."
- `src/engine/grade.ts`, order items: name the broken clue's words as well as its number ("This line breaks clue 2, “Ava finished before Ben.”"). Do this only together with the existing grade tests and `wrong-answers.test.ts`, which match `^This line breaks clues? `.
